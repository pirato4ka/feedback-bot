# 🛡 Гражданский патруль — бот для приёма сведений

Telegram-бот для русской общины: жители передают администрации сведения любого формата
(текст, фото, видео, документы, голосовые, кружки, геолокации, контакты, опросы, стикеры),
а администраторы обрабатывают обращения и делают разовые или периодические рассылки.

## Возможности

**Для жителей**

- 📨 Обращение в 3 шага: тема → сообщение любого типа → проверка и отправка.
- 🆘 Отдельная кнопка «Срочно» с напоминанием звонить 112.
- 🕶 Анонимность по умолчанию: имя и username скрыты, переключается на карточке обращения.
- 💬 Ответ администрации приходит в личный чат с ботом.
- ⏱ Антифлуд: одно обращение в `REPORT_COOLDOWN_SECONDS` секунд (по умолчанию 60).
- ℹ️ Справка по правилам и ограничениям.

**Для администраторов**

- 📊 Статистика: пользователи, обращения, рассылки, активность за 24 часа.
- 📨 Список обращений с постраничным просмотром, карточкой, повторной отправкой контента.
- ✅ Статусы: новое / есть ответ / обработано / спам.
- 💬 Ответ информатору любым типом сообщения — от имени бота, без раскрытия личности админа.
- 📥 Экспорт всех обращений в CSV (разделитель `;`, UTF-8 BOM — открывается в Excel).
- 📢 Рассылки: разовые и периодические (интервал от 1 минуты до 30 дней),
  пауза/возобновление, ручной запуск, удаление, отчёт о доставке.

## Быстрый старт

```bash
# 1. Виртуальное окружение и зависимости
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux/macOS
pip install -r requirements.txt

# 2. Настройки
copy .env.example .env          # Windows
# cp .env.example .env          # Linux/macOS
# отредактируйте .env: BOT_TOKEN и ADMIN_IDS

# 3. Запуск
python run.py
```

Требуется Python 3.11+.

## Переменные окружения

| Переменная | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен из @BotFather |
| `ADMIN_IDS` | да | — | ID администраторов через запятую |
| `ADMIN_CHAT_ID` | нет | — | Общий чат для обращений; если пусто — личные чаты админов |
| `DB_PATH` | нет | `data/bot.db` | Путь к SQLite-базе |
| `REPORT_COOLDOWN_SECONDS` | нет | `60` | Пауза между обращениями пользователя |
| `SCHEDULER_TICK_SECONDS` | нет | `20` | Период проверки расписания рассылок |
| `BROADCAST_RATE_PER_SECOND` | нет | `20` | Скорость рассылки, сообщений/сек |
| `DISPLAY_UTC_OFFSET` | нет | `3` | Часовой пояс для отображения времени |

## Как это работает

**Любой тип содержимого.** Входящее сообщение сохраняется в базу как JSON
(`Message.model_dump`), при доставке восстанавливается и отправляется через
`Message.send_copy` — так администрация получает фото, видео, кружки, опросы и т. д.
без потери исходного вида. Кнопки и «эффекты» из сохранённого сообщения вырезаются.

**Обращения.** При отправке создаётся запись в `reports` и копия уходит в `ADMIN_CHAT_ID`
(или каждому администратору) с кнопками «Обработано / Ответить / Спам». Если контент
переслать не удалось, администратор получает уведомление и может открыть обращение
в панели.

**Анонимность.** По умолчанию имя и username скрыты, но `user_id` хранится в базе —
без него невозможен ответ и защита от спама. Режим переключается на карточке перед отправкой.

**Рассылки.** Рассылка хранится как сохранённое сообщение (`broadcasts.payload`).
Планировщик раз в `SCHEDULER_TICK_SECONDS` секунд выбирает рассылки с наступившим
`next_run_at`, отправляет их всем не заблокировавшим бота пользователям с ограничением
скорости, пишет прогон в `broadcast_runs` и присылает отчёт создателю. Периодическая
рассылка после отправки получает новое `next_run_at`; при ошибке «бот заблокирован»
пользователь помечается неактивным и исключается из следующих рассылок.

## Структура проекта

```
rs-info-bot/
├── run.py                  # точка входа
├── requirements.txt
├── .env.example
└── bot/
    ├── main.py             # сборка Dispatcher, запуск polling
    ├── config.py           # настройки из .env
    ├── db.py               # SQLite: пользователи, обращения, рассылки
    ├── keyboards.py        # reply/inline клавиатуры
    ├── middlewares.py      # регистрация пользователей, фильтр администратора
    ├── scheduler.py        # фоновый планировщик рассылок
    ├── sender.py           # отправка контента любого типа
    ├── texts.py            # все тексты интерфейса
    ├── utils.py            # время, интервалы, обрезка текста
    └── handlers/
        ├── common.py       # /start, /help, /cancel, меню
        ├── report.py       # приём обращений
        ├── admin.py        # статистика, обращения, ответы, экспорт
        ├── broadcasts.py   # управление рассылками
        └── fallback.py     # ответы на неожиданные сообщения
```

## Данные

- База: `data/bot.db` (SQLite, режим WAL).
- Экспорт CSV: `data/exports/reports_YYYYMMDD_HHMMSS.csv`.
- Каталог `data/` создаётся автоматически, его не нужно коммитить.

## Продакшен

- Запускайте бота под супервизором (systemd, Docker, NSSM) — процесс должен
  перезапускаться при падении.
- Один токен — один запущенный экземпляр (polling), иначе Telegram будет отдавать
  обновления случайному процессу.
- Резервируйте `data/bot.db` (вместе с `-wal`/`-shm` или через `sqlite3 .backup`).
- При большом числе пользователей уменьшите `BROADCAST_RATE_PER_SECOND`
  (Telegram ограничивает ~30 сообщений/сек).

## Ограничения

- Бот не заменяет экстренные службы: при угрозе жизни нужно звонить 112.
- Медиа хранятся как ссылки на файлы Telegram (`file_id`), поэтому при удалении
  исходного сообщения из чата информатора контент может стать недоступен.
- Состояния диалогов хранятся в памяти: после перезапуска незавершённые черновики
  теряются (сохранённые обращения и рассылки — нет).
